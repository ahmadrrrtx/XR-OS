# XR Security — Implementation Status

What the independent audit (v7.1.0 "Truth") verified **live**, what degrades honestly, and
what is explicitly not claimed. Claims here mirror `release.manifest.json` evidence and are
policed by claim-lint; do not edit this file into marketing.

## Verified in the running product (audit-executed)

| Mechanism | Status |
|---|---|
| Single tool registry, single routing authority, one execution envelope | verified single-authority |
| Deterministic policy gate + risk classification | verified |
| Human-approval gates on consequential actions | verified |
| Hash-chained audit log (`xr verify-log`, halt-and-alert on break) | verified live |
| Fail-closed egress allow-list, private-IP blocking, URL canonicalization | verified |
| Secrets in OS keychain with redaction | verified |
| Placement lattice (in-process → restricted-process → bubblewrap) | verified, honest degradation |
| Dashboard loopback-only + bearer token + strict cookie/frame headers | probed live |
| Plugin tree-hash + permission model; MCP allow-list client | verified |
| Release manifest drift gates + claim-lint | verified in CI |

## Honest degradations (stated, not hidden)

- Container/gVisor tiers are **not available** on every OS; the lattice reports the real
  guarantee per platform rather than implying one.
- Voice stack is code-real but **hardware-unverified** (text fallback documented).
- The in-process VM realm used by the plugin loader is defense-in-depth only — it is not a
  security boundary (see `docs/security/POSTURE.md`).

## Not claimed (P-13)

- No SOC 2 / ISO 27001 / HIPAA / PCI-DSS / FedRAMP certification; no external audit exists.
- No "provable security": deterministic screening + fail-closed policy gate, stated plainly.
- No signed release history predating the publish-lockstep work; the first lockstep-signed
  release is tracked in the ratification checklist (A-3).
- Self-referential evaluation harnesses are labeled self-evaluation, not benchmarks.
